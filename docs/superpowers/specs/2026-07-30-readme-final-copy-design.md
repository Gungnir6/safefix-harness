# README 最终交付措辞设计

## 目标

将 README 从开发过程说明调整为最终课程交付入口，使教师和首次访问者能够快速找到在线 WebUI、CLI Release、验收命令、机制说明和安全边界。只修改文案与章节组织，不改变代码、命令或产品行为。

## 方案比较

1. **课程验收优先，同时兼顾普通用户（采用）**：首页先给出三个交付入口和三项核心机制，再说明安装、演示、凭据、安全与限制。最符合当前交付目的。
2. **产品用户优先**：弱化课程背景，按通用 CLI 产品写法组织。更像正式产品，但教师需要额外寻找作业机制证据。
3. **仅修正错误句子**：保留现有结构，只删除过时表述。改动最少，但首页重点仍不够清晰。

学生已确认采用方案 1。

## 结构

1. 项目简介与交付入口：GitHub、v0.1.1 Release、Render WebUI。
2. 核心机制：安全护栏、验证反馈闭环、一次性审批。
3. 快速体验：优先在线 WebUI，其次 `safefix-demo all`。
4. 安装与本地运行：明确仅支持 Python 3.12。
5. 完整 Mock 修复流程与可选真实模型凭据配置。
6. 架构、项目结构、分发、安全边界、已知限制和第三方依赖。
