# SafeFix 中文引导演示 WebUI 设计

## 目标

让第一次接触 SafeFix 的学生或教师在不阅读源码的情况下理解：项目是约束代码 Agent 的安全运行框架，能够拦截危险动作、根据验证反馈继续修复，并对敏感动作设置人工检查点。

本次只优化展示与交互，不修改策略、审批、工具、审计或 API 的安全语义。

## 选定方案

采用“引导演示控制台”方案：保留现有深色工业控制台视觉和技术细节，同时把核心结论、场景说明、状态及错误改为中文。相比单纯翻译，它能解释每个演示证明什么；相比重新开发分步向导，它能复用现有路由和数据结构，适合快速交付。

## 页面设计

### 全局

- 页面语言设置为中文。
- 导航、页脚、按钮、状态、错误信息和设置页统一中文化。
- 保留 `SafeFix`、CLI、API、Agent、Mock 等必要产品或技术名称。
- 保留键盘操作、焦点样式、`aria-live` 和响应式布局。

### 首页

- 标题明确为“安全地修复代码，把权限留在人手里”。
- 公开演示模式显示醒目标识，说明不会访问真实项目、不会调用真实模型、不会使用 API Key。
- 三个场景使用可点击卡片而不是下拉框：
  - 安全边界：危险命令被策略拒绝，工具调用次数为零。
  - 验证反馈：第一次补丁错误，测试失败后再次修改并通过。
  - 一次性审批：敏感动作需要批准，批准能力不能重复使用。
- 每张卡片显示“证明什么”和预期结果。
- 公开模式删除无效的“修复目标”文本框；本地模式继续显示项目路径、模型提供方和修复目标。
- 主按钮改为“运行这个演示”。

### 结果页

- 场景名、运行状态和工作区说明使用中文。
- 顶部给出用户可直接理解的结论，例如“演示成功”“危险动作已拦截”。
- 时间线每项包含中文标题与解释。
- 原始事件码和脱敏 JSON 放入可展开的“查看技术细节”，既方便演示，也保留审计证据。
- 审批按钮和说明中文化，明确批准只适用于冻结的单次动作。

### 设置页

- 将凭据状态、项目记忆和清理操作中文化。
- 公开演示模式继续只展示 Mock 状态，不允许录入或回显真实密钥。

## 展示数据

公开演示事件继续保留稳定的机器事件码，同时增加确定性的中文摘要。服务端渲染使用中文摘要；技术详情继续显示原始事件码。通用运行事件根据 `event_type` 使用固定中文标签，未知事件回退为格式化后的原始名称。

状态和前端错误使用固定映射表翻译；未知错误仍显示稳定错误码，避免吞掉诊断信息。

## 安全与错误处理

- 所有模型、工具和事件内容继续由 Jinja 自动转义或通过 `textContent` 插入。
- 不使用 `innerHTML` 渲染动态内容。
- 不改变公开模式的路径、provider、限流和并发限制。
- API 失败时恢复提交按钮，并显示中文提示与稳定错误码。

## 验证

- 页面测试覆盖中文导航、三张场景卡、公开模式无任务文本框、本地模式仍保留任务输入。
- 结果页测试覆盖中文状态、中文事件摘要、技术详情及 HTML 转义。
- API 测试继续覆盖真实 `PublicDemoService` 的异步调用。
- 手工在浏览器运行三个公开场景，确认均可进入结果页并显示可理解的中文时间线。
- 运行完整 pytest、Ruff、mypy 和 GitHub Actions。

## 非目标

- 不接入真实大模型。
- 不实现任意项目的开箱即用自动修复。
- 不重写后端状态机或审批流程。
- 不新增账号系统、持久化数据库或部署平台功能。
