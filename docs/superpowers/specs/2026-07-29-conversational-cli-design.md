# SafeFix 轻量对话式 CLI 设计

## 目标

让安装 Release 的普通用户在项目目录执行 `safefix` 后，能够用自然语言连续提交修复任务，而不必为每次执行填写完整参数。现有 `safefix run` 继续作为脚本、CI 和可复现实验入口。

## 方案比较

1. **推荐：轻量 REPL，复用现有运行时。** 开发量小，能提供真实的对话体验，并继续使用现有隔离工作区、策略、审批、验证和审计机制。
2. 完整全屏 TUI。体验更接近 OpenCode，但需要终端渲染、快捷键、会话布局等大量非核心工作，不适合作业当前阶段。
3. 只保留单次命令。实现成本最低，但首次配置和日常使用仍然繁琐，不能解决用户已经发现的体验问题。

本轮采用方案 1。

## 用户入口

```text
cd <project>
safefix

SafeFix > 修复当前项目里失败的测试
SafeFix > 再检查一下类型错误
SafeFix > /diff
SafeFix > /exit
```

`safefix chat [project]` 是显式等价入口。无子命令的 `safefix` 默认在当前目录启动对话模式。

## 首次配置

启动对话模式时：

1. 优先读取显式 `--config`，否则读取当前项目的 `safefix.yaml`。
2. 配置不存在时，询问 endpoint 和 model，并生成可直接运行的配置；直接回车采用 OpenAI-compatible 默认值。
3. 真实 provider 尚无凭据时，使用隐藏输入读取 API Key，并通过现有 `CredentialService` 保存；任何输出都不得包含密钥。
4. 配置或凭据保存失败时，显示简短可操作错误，不输出 Python traceback。

为便于单独配置，同时增加 `safefix setup [project]`。对话启动时调用同一配置逻辑，避免两套行为。

## 对话行为

- 普通非空输入作为一个新任务，交给现有 `run_cli` 执行。
- 同一进程内可以连续执行多个任务；每个任务仍创建独立、持久化的隔离工作区。
- 每次任务结束后显示现有运行摘要，再返回提示符。
- EOF、`/exit` 和 `/quit` 正常退出；空输入不执行任务。
- `/help` 显示可用命令。
- `/status` 显示最近一次任务的退出状态和结果工作区。
- `/diff` 对最近一次隔离工作区执行只读 `git diff --no-ext-diff --`；不存在最近任务或不是 Git 仓库时给出说明。
- `/new` 清除当前会话记录中的“最近一次任务”，不删除工作区或审计记录。
- 本轮不实现跨进程恢复、流式 token、文件补全、Shell 快捷执行或全屏 TUI。

## 代码边界

- `cli.py`：解析 `chat`、`setup` 和无参数默认入口。
- 新增 `cli_setup.py`：负责配置与凭据向导。
- 新增 `cli_chat.py`：负责 REPL、斜杠命令和连续任务调度。
- `cli_runner.py`：保持单次真实任务的唯一执行路径；仅增加返回最近运行结果所必需的窄接口，不复制 AgentLoop。

三个模块通过可注入的输入、输出和 runner 函数测试，避免测试访问网络、系统 keyring 或真实终端。

## 错误与安全

- API Key 使用隐藏输入并存入现有凭据服务。
- 默认继续使用隔离工作区；对话模式不提供隐式 `--in-place`。
- 配置、凭据、项目路径和任务执行错误只影响当前任务；可恢复错误返回提示符。
- `/diff` 只运行固定参数的只读 Git 命令，不拼接用户输入。
- Ctrl+C 中止当前提示或任务后安全返回/退出，不打印 traceback。

## 验收标准

1. 无参数 `safefix` 在当前目录进入对话模式。
2. 首次运行可生成有效配置并安全保存凭据。
3. 连续两条自然语言输入会调用两次现有真实 runner。
4. `/help`、`/status`、`/diff`、`/new`、`/exit` 行为有自动化测试。
5. 现有 `safefix run`、WebUI 和全部测试保持兼容。
6. README、PLAN 和 AGENT_LOG 记录新的安装后使用流程。
